## 1. Users

**Purpose:** Stores all system users — Donors, NGOs, Volunteers, and Admins.

| # | Column | Data Type | Nullable | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | UserId | INT | NO | IDENTITY(1,1) | PRIMARY KEY | Unique user identifier. Auto-incremented by SQL Server. |
| 2 | FullName | NVARCHAR(100) | NO | — | — | User's full name. Unicode support for Indian names. |
| 3 | Email | NVARCHAR(255) | NO | — | UNIQUE (UQ_Users_Email) | Login email address. Must be unique across all users. |
| 4 | PasswordHash | NVARCHAR(500) | NO | — | — | Hashed password. Never stores plain text. Generated by ASP.NET Core Identity or BCrypt. |
| 5 | Role | NVARCHAR(20) | NO | — | CHECK (CK_Users_Role) | User type. Allowed: 'Donor', 'NGO', 'Volunteer', 'Admin'. |
| 6 | Phone | NVARCHAR(20) | YES | NULL | — | Optional phone number. |
| 7 | IsActive | BIT | NO | 1 | — | Soft-delete flag. 1 = active, 0 = deactivated. |
| 8 | CreatedAt | DATETIME2 | NO | SYSDATETIME() | — | Record creation timestamp. |
| 9 | UpdatedAt | DATETIME2 | NO | SYSDATETIME() | — | Last modification timestamp. Updated by backend on every change. |

## 2. NGOProfiles

**Purpose:** Stores additional details for NGO-role users. One-to-one relationship with Users.

| # | Column | Data Type | Nullable | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | NGOProfileId | INT | NO | IDENTITY(1,1) | PRIMARY KEY | Unique profile identifier. |
| 2 | UserId | INT | NO | — | UNIQUE, FK → Users(UserId) ON DELETE CASCADE | Links to the Users table. UNIQUE ensures one-to-one. |
| 3 | OrganizationName | NVARCHAR(200) | NO | — | — | Registered name of the NGO. |
| 4 | MaximumCapacity | DECIMAL(10,2) | NO | — | CHECK > 0 (CK_NGOProfiles_MaximumCapacity) | Maximum food the NGO can handle at a time. |
| 5 | CapacityUnit | NVARCHAR(20) | NO | — | — | Unit for capacity: 'kg', 'meals', 'litres', etc. |
| 6 | Location | NVARCHAR(500) | NO | — | — | NGO's address or service area. |
| 7 | IsVerified | BIT | NO | 0 | — | Whether an admin has verified this NGO. 0 = pending, 1 = verified. |
| 8 | CreatedAt | DATETIME2 | NO | SYSDATETIME() | — | Record creation timestamp. |
| 9 | UpdatedAt | DATETIME2 | NO | SYSDATETIME() | — | Last modification timestamp. |

## 3. NGOAcceptedCategories

**Purpose:** Stores which food categories each NGO accepts. One row per category per NGO (normalized, 1NF).

| # | Column | Data Type | Nullable | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | NGOAcceptedCategoryId | INT | NO | IDENTITY(1,1) | PRIMARY KEY | Unique row identifier. |
| 2 | NGOProfileId | INT | NO | — | FK → NGOProfiles(NGOProfileId) ON DELETE CASCADE | Which NGO profile this category belongs to. |
| 3 | FoodCategory | NVARCHAR(50) | NO | — | UNIQUE with NGOProfileId | Food category name, e.g., 'Cooked Food', 'Raw Vegetables'. |
| 4 | IsActive | BIT | NO | 1 | — | Whether this category is currently active. |

**Composite UNIQUE constraint:** `UQ_NGOAcceptedCategories_Profile_Category` on `(NGOProfileId, FoodCategory)` prevents duplicate categories for the same NGO.

## 4. Donations

**Purpose:** Stores surplus food donation listings created by Donor users.

| # | Column | Data Type | Nullable | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | DonationId | INT | NO | IDENTITY(1,1) | PRIMARY KEY | Unique donation identifier. |
| 2 | DonorId | INT | NO | — | FK → Users(UserId) ON DELETE NO ACTION | The donor who created this listing. NO ACTION preserves history. |
| 3 | FoodName | NVARCHAR(200) | NO | — | — | Name of the food item, e.g., "Chicken Biryani". |
| 4 | FoodCategory | NVARCHAR(50) | NO | — | — | Category for NGO matching, e.g., "Cooked Food". |
| 5 | Quantity | DECIMAL(10,2) | NO | — | CHECK > 0 (CK_Donations_Quantity) | Amount of food being donated. Must be positive. |
| 6 | Unit | NVARCHAR(20) | NO | — | — | Unit: 'kg', 'meals', 'litres', 'packets', etc. |
| 7 | FoodCondition | NVARCHAR(50) | NO | — | CHECK (CK_Donations_FoodCondition) | Condition: 'Fresh', 'Near Expiry', 'Leftover', 'Packed'. |
| 8 | StorageType | NVARCHAR(50) | NO | — | CHECK (CK_Donations_StorageType) | Storage: 'Refrigerated', 'Room Temperature', 'Frozen'. |
| 9 | PickupDeadline | DATETIME2 | NO | — | — | Deadline by which food must be picked up. |
| 10 | PickupAddress | NVARCHAR(500) | NO | — | — | Donor's address for food pickup. |
| 11 | Description | NVARCHAR(1000) | YES | NULL | — | Optional notes from the donor. |
| 12 | Status | NVARCHAR(20) | NO | 'Available' | CHECK (CK_Donations_Status) | Current workflow status. See allowed values below. |
| 13 | UrgencyScore | DECIMAL(5,2) | NO | 0 | CHECK 0–100 (CK_Donations_UrgencyScore) | Calculated urgency (0 = none, 100 = maximum). |
| 14 | UrgencyLevel | NVARCHAR(10) | NO | 'Low' | CHECK (CK_Donations_UrgencyLevel) | Label: 'Critical', 'High', 'Medium', 'Low'. |
| 15 | RecipientNgoId | INT | YES | NULL | FK → Users(UserId) | NGO user who claimed/accepted the donation. |
| 16 | CreatedAt | DATETIME2 | NO | SYSDATETIME() | — | Record creation timestamp. |
| 17 | UpdatedAt | DATETIME2 | NO | SYSDATETIME() | — | Last modification timestamp. |

## 5. VolunteerAssignments

**Purpose:** Tracks volunteer pickup and delivery dispatch records created when an NGO assigns a volunteer or a volunteer accepts a rescue task.

| # | Column | Data Type | Nullable | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | AssignmentId | INT | NO | IDENTITY(1,1) | PRIMARY KEY | Unique assignment identifier. |
| 2 | DonationId | INT | NO | — | UNIQUE, FK → Donations(DonationId) | Donation linked to this delivery assignment. |
| 3 | VolunteerId | INT | NO | — | FK → Users(UserId) | Volunteer assigned to the delivery. |
| 4 | AssignedByNgoId | INT | NO | — | FK → Users(UserId) | NGO user who initiated the assignment. |
| 5 | AssignedAt | DATETIME2 | NO | SYSDATETIME() | — | Timestamp when volunteer was assigned. |
| 6 | Status | NVARCHAR(20) | NO | 'Assigned' | CHECK (CK_VolunteerAssignments_Status) | Allowed: 'Assigned', 'PickedUp', 'Delivered', 'Completed', 'Cancelled'. |

## 6. PickupTasks

**Purpose:** Tracks the pickup and delivery process after an NGO accepts a donation.

| # | Column | Data Type | Nullable | Default | Constraints | Description |
|---|---|---|---|---|---|---|
| 1 | PickupTaskId | INT | NO | IDENTITY(1,1) | PRIMARY KEY | Unique task identifier. |
| 2 | DonationId | INT | NO | — | UNIQUE, FK → Donations(DonationId) ON DELETE CASCADE | One task per donation (MVP). |
| 3 | NGOId | INT | NO | — | FK → Users(UserId) ON DELETE NO ACTION | NGO that accepted the donation. |
| 4 | VolunteerId | INT | YES | NULL | FK → Users(UserId) ON DELETE SET NULL | Volunteer assigned to pickup. NULL until assigned. |
| 5 | AssignedAt | DATETIME2 | YES | NULL | — | When the volunteer was assigned. |
| 6 | ScheduledPickupTime | DATETIME2 | YES | NULL | — | Planned pickup time. |
| 7 | ActualPickupTime | DATETIME2 | YES | NULL | — | When food was actually picked up. |
| 8 | ActualDeliveryTime | DATETIME2 | YES | NULL | — | When food was actually delivered to NGO. |
| 9 | Status | NVARCHAR(20) | NO | 'Pending' | CHECK (CK_PickupTasks_Status) | Task workflow status. |
| 10 | Notes | NVARCHAR(1000) | YES | NULL | — | Optional notes about the task. |
| 11 | CreatedAt | DATETIME2 | NO | SYSDATETIME() | — | Record creation timestamp. |
| 12 | UpdatedAt | DATETIME2 | NO | SYSDATETIME() | — | Last modification timestamp. |

## 7. Constraints Summary

### Primary Keys

| Constraint Name | Table | Column |
|---|---|---|
| PK_Users | Users | UserId |
| PK_NGOProfiles | NGOProfiles | NGOProfileId |
| PK_NGOAcceptedCategories | NGOAcceptedCategories | NGOAcceptedCategoryId |
| PK_Donations | Donations | DonationId |
| PK_VolunteerAssignments | VolunteerAssignments | AssignmentId |
| PK_PickupTasks | PickupTasks | PickupTaskId |

### Unique Constraints

| Constraint Name | Table | Column(s) | Purpose |
|---|---|---|---|
| UQ_Users_Email | Users | Email | No duplicate email addresses |
| UQ_NGOProfiles_UserId | NGOProfiles | UserId | One profile per user (1:1) |
| IX_VolunteerAssignments_DonationId | VolunteerAssignments | DonationId | One assignment per donation |
| UQ_PickupTasks_DonationId | PickupTasks | DonationId | One task per donation (MVP) |
| UQ_NGOAcceptedCategories_Profile_Category | NGOAcceptedCategories | (NGOProfileId, FoodCategory) | No duplicate categories per NGO |

### Foreign Keys

| Constraint Name | From Table.Column | To Table.Column | ON DELETE | ON UPDATE |
|---|---|---|---|---|
| FK_NGOProfiles_Users | NGOProfiles.UserId | Users.UserId | CASCADE | CASCADE |
| FK_NGOAcceptedCategories_NGOProfiles | NGOAcceptedCategories.NGOProfileId | NGOProfiles.NGOProfileId | CASCADE | CASCADE |
| FK_Donations_Users | Donations.DonorId | Users.UserId | NO ACTION | CASCADE |
| FK_Donations_Users_RecipientNgoId | Donations.RecipientNgoId | Users.UserId | NO ACTION | NO ACTION |
| FK_VolunteerAssignments_Donations_DonationId | VolunteerAssignments.DonationId | Donations.DonationId | NO ACTION | NO ACTION |
| FK_VolunteerAssignments_Users_VolunteerId | VolunteerAssignments.VolunteerId | Users.UserId | NO ACTION | NO ACTION |
| FK_VolunteerAssignments_Users_AssignedByNgoId | VolunteerAssignments.AssignedByNgoId | Users.UserId | NO ACTION | NO ACTION |
| FK_PickupTasks_Donations | PickupTasks.DonationId | Donations.DonationId | CASCADE | CASCADE |
| FK_PickupTasks_NGO | PickupTasks.NGOId | Users.UserId | NO ACTION | NO ACTION |
| FK_PickupTasks_Volunteer | PickupTasks.VolunteerId | Users.UserId | SET NULL | NO ACTION |

### CHECK Constraints

| Constraint Name | Table | Rule |
|---|---|---|
| CK_Users_Role | Users | Role IN ('Donor', 'NGO', 'Volunteer', 'Admin') |
| CK_Donations_Quantity | Donations | Quantity > 0 |
| CK_Donations_UrgencyScore | Donations | UrgencyScore >= 0 AND UrgencyScore <= 100 |
| CK_Donations_UrgencyLevel | Donations | UrgencyLevel IN ('Critical', 'High', 'Medium', 'Low') |
| CK_Donations_Status | Donations | Status IN ('Available', 'Accepted', 'Assigned', 'PickedUp', 'Delivered', 'Completed', 'Rejected', 'Cancelled', 'Expired', 'Failed') |
| CK_Donations_FoodCondition | Donations | FoodCondition IN ('Fresh', 'Near Expiry', 'Leftover', 'Packed') |
| CK_Donations_StorageType | Donations | StorageType IN ('Refrigerated', 'Room Temperature', 'Frozen') |
| CK_NGOProfiles_MaximumCapacity | NGOProfiles | MaximumCapacity > 0 |
| CK_VolunteerAssignments_Status | VolunteerAssignments | Status IN ('Assigned', 'PickedUp', 'Delivered', 'Completed', 'Cancelled') |
| CK_PickupTasks_Status | PickupTasks | Status IN ('Pending', 'Assigned', 'PickedUp', 'Delivered', 'Failed', 'Cancelled') |

## 9. Allowed Values Reference

### User Roles

| Value | Description |
|---|---|
| Donor | Creates surplus food donations |
| NGO | Accepts and redistributes food |
| Volunteer | Picks up and delivers food |
| Admin | Monitors and manages the system |

### Donation Statuses

| Value | Description | Terminal? |
|---|---|---|
| Available | Newly created, waiting for NGO | No |
| Accepted | NGO has accepted the donation | No |
| Assigned | Volunteer has been assigned | No |
| PickedUp | Volunteer picked up the food | No |
| Delivered | Food delivered to NGO | No |
| Completed | Successfully redistributed | Yes |
| Rejected | NGO rejected the donation | Yes |
| Cancelled | Cancelled by donor or NGO | Yes |
| Expired | Pickup deadline passed | Yes |
| Failed | Pickup or delivery failed | Yes |

### Pickup Task Statuses

| Value | Description | Terminal? |
|---|---|---|
| Pending | Waiting for volunteer assignment | No |
| Assigned | Volunteer assigned | No |
| PickedUp | Food picked up | No |
| Delivered | Food delivered to NGO | Yes |
| Failed | Pickup or delivery failed | Yes |
| Cancelled | Task cancelled | Yes |

### Food Conditions

| Value | Description |
|---|---|
| Fresh | Freshly prepared or harvested |
| Near Expiry | Close to expiration date |
| Leftover | From an event or service |
| Packed | Sealed/packaged food |

### Storage Types

| Value | Description |
|---|---|
| Refrigerated | Requires cold storage |
| Room Temperature | Can be stored at room temperature |
| Frozen | Requires freezer storage |

### Urgency Levels

| Value | Score Range | Description |
|---|---|---|
| Critical | 76 – 100 | Needs immediate action |
| High | 51 – 75 | Should be addressed soon |
| Medium | 26 – 50 | Moderate priority |
| Low | 0 – 25 | No immediate urgency |
